# 项目全局认知

本文档主要负责梳理 License Manager 面向 Python 开发者翻写过程中的整体文件存放策略，以及包结构的宏观认知。

由于原始开发使用 Go 语言，部分文件习惯（如根域名即包名）并不完全适用 Python（考虑到 Python 中不合法的 "-" 命名）。因此，对于 Python SDK，我们采取如下被业界广泛遵循的标准 Python 包（Package）部署和命名规范。

│   ├── 翻写计划.md                # 各个批次的 DAG 执行计划和阶段任务

## Python 设计与 Go 的核心差异
1. **统一入口**：所有模块收拢在合规的包名 `license_manager` 下，用户只需在外部调用 `import license_manager as license`，然后使用 `license.Client(cfg)`。
2. **并发与定时任务**：相较于 Go 语言轻量级的 Goroutine 处理后台心跳和回调触发，Python 需要通过启动后台 Daemon 线程 `threading.Thread` 进行心跳轮询，并在进行锁处理或休眠时关注 GIL 和中断异常捕获结构。
3. **日志框架对接**：Python 提供更系统完整的 `logging` 模块机制，在此不一定需要过多自定义，只需注入正确的 `logger` 组件即可。
