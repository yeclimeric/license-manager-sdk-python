# License Manager 客户端模拟器 - 设计文档

## 1. 项目概述

### 1.1 项目名称与定位

本项目是 **License Manager SDK for Python** 的客户端演示程序（Demo），用于演示机器视觉检测软件的灵活授权方案。

- **产品标识**：`vision-vm-studio`
- **版本号**：`1.0.0`
- **目标用户**：软件发行商、终端客户（机器视觉检测场景）
- **技术栈**：Python 3 + Tkinter GUI + License Manager SDK

### 1.2 核心功能定位

本演示程序模拟一个商业软件的客户端授权模块，具备以下核心能力：

1. **设备指纹采集**：自动采集本机硬件信息生成唯一设备标识
2. **在线授权激活**：连接 SaaS 平台完成授权绑定
3. **离线授权支持**：通过脱机包实现物理隔离环境的授权验证
4. **外网/内网双模式业务**：同一套校验逻辑，支持模拟外网在线和内网离线两种运行环境
5. **本地缓存复用**：历史授权自动加载，无需重复输入激活码
6. **后台心跳保活**：定期向服务器上报在线状态
7. **业务阻断能力**：未授权或授权失效时拒绝执行业务逻辑
8. **实时状态反馈**：UI 实时展示授权状态与到期时间

## 3. 功能设计

### 3.1 UI 布局与交互

程序主窗口尺寸为 **700×650**，包含三个区域：

#### 区域一：设备指纹与当前授权状态

- **设备指纹字段**（只读）：显示本机 SHA-256 硬件指纹，用于唯一标识这台设备
- **复制按钮**：一键复制指纹到剪贴板
- **授权状态标签**：`未激活`（红色）/ `验证通过 (合法)`（绿色）/ `锁定: 原因`（红色）
- **到期时间标签**：显示证书过期时间，永久授权显示 "永久"

#### 区域二：管控与激活设置

- **SaaS 服务地址**：默认 `http://43.136.177.43:18081`，可由用户修改
- **RSA 公钥（PEM）**：预填充 RSA-2048 公钥，用于验签服务端下发的许可证
- **产品激活码输入框**：可选。留空时「激活 / 验证」与业务按钮仅尝试加载并校验本地 `license.lic`（占位激活码 `LOADED_FROM_LOCAL_CACHE`）；填写时支持纯在线码或含脱机包（`&` 分隔）
- **激活/验证按钮**：手动触发激活/验证流程
- **清理本地许可缓存按钮**：物理删除 `license.lic`，重置授权状态
- **创建/修改许可证按钮**：弹窗直接读取/编辑/新建 `license.lic`，不做任何格式校验，用户可粘贴任意内容保存

#### 区域三：机器视觉核心业务模拟与日志

- **外网业务按钮**：`[业务] AI 模板检测`（蓝色），联网环境下执行业务
- **模拟断网开关**：勾选后强制模拟内网断网，降级走脱机包验证路径
- **日志输出区**：黑色背景滚动文本，显示所有操作与回调日志（时间戳格式 HH:MM:SS）

### 3.2 启动行为（重要变更）

**程序启动时不再自动初始化 SDK 和心跳**。

启动流程改为：

1. 仅采集设备指纹并显示在 UI
2. 日志提示：激活码可留空，仅验证本地许可；填写后可在线激活或带脱机包降级。
3. 等待用户点击「激活 / 验证」或业务按钮，才触发授权校验（不会在启动时自动初始化 SDK）。

这一变更确保了：
- 程序打开时不会偷偷开始运行（无心跳、无网络请求）
- 激活码非必填：无码时依赖已有 `license.lic`，有码时走在线/降级流程
- 用户对"何时开始"有完全的掌控感

### 3.3 授权流程

#### 3.3.1 手动激活流程（"激活 / 验证"按钮）

用户手动点击"激活/验证"按钮时触发：

- **激活码为空**：不删除 `license.lic`，使用占位激活码 `LOADED_FROM_LOCAL_CACHE` 初始化 SDK，仅从本地加载；若无本地文件则提示并失败。

有激活码时：

1. **输入解析**：区分纯在线授权码与包含脱机包的激活码（后者以 `&` 分隔）
2. **模拟断网开启**：**不删除**本地 `license.lic`；若文件存在则优先用本地缓存初始化并验证，成功即结束；失败且无脱机包则阻断（**保留本地文件**）。若有脱机包则继续尝试在线激活（预期失败）后按脱机包降级写入。
3. **联网（未勾选模拟断网）**：删除旧 `license.lic` 后再走全新在线激活
4. **优先在线**：尝试连接 SaaS `/api/v1/activate` 接口
5. **激活成功**：SDK 保存证书文件，启动心跳，UI 更新状态
6. **激活失败**：
   - 若存在脱机包 → 降级执行离线验证
   - 若无脱机包 → 阻断并提示错误

#### 3.3.2 业务按钮触发流程

点击业务按钮时，**同一套业务入口**（`_biz_thread`）被调用，网络模式由"模拟断网"开关控制：

- **激活码为空（仅本地）**：不删除 `license.lic`；占位激活码 `LOADED_FROM_LOCAL_CACHE`；若勾选「模拟断网」则拦截 `requests.Session.post`（与有码路径一致），心跳持续尝试但失败；未勾选则真实联网心跳。

有激活码时：

**Step 1**：读取"模拟断网"开关状态；勾选则注入 HTTP 拦截（激活与心跳同一套 `Session.post`）

**Step 2**：若已存在旧 client，先关闭释放资源

**Step 3**（仅内网断网模式）：检测本地 `license.lic` 是否存在

- **存在** → 直接用本地缓存做离线验证 → 通过则放行业务（不再尝试在线激活）；失败则**保留本地文件并阻断**，提示用户联网后重试
- **不存在** → 继续 Step 4

**Step 4**：清理旧的 `license.lic` 文件

**Step 5**：尝试在线激活

- **成功** → 进入 Step 7
- **失败** → 进入 Step 6

**Step 6**：在线失败时降级处理

- **有脱机包** → 写入脱机包文件，重新初始化 SDK（若仍为模拟断网，不解除拦截）
- **无脱机包** → 阻断并报错

**Step 7**：执行业务校验（`client.validate()`）

- **通过** → 显示业务层提示，AI 算法启动
- **失败** → 弹出越权阻断警告

**Step 9**：若当前开关为「联网」，移除拦截；若为「断网」，保持拦截直至用户关闭开关、清理缓存或再次以联网方式运行业务

### 3.4 外网模式 vs 内网模式

| 维度 | 外网环境 | 内网环境 |
|------|----------|----------|
| **开关状态** | 未勾选"模拟断网" | 勾选"模拟断网" |
| **网络状态** | 正常联网 | 通过 mock 拦截 `Session.post`（模拟网络故障） |
| **激活路径** | 在线激活 → 成功 | 优先用本地缓存验证（断网模式下直接放行）；本地缓存无效时才尝试在线激活 → 失败则降级离线（有脱机包时） |
| **心跳** | 启用（10s），正常上报 | 始终运行；断网时被拦截失败；**关闭开关后立即恢复真实上报** |
| **校验逻辑** | 完全相同 | 完全相同 |
| **前提条件** | 需联网 + 激活码（或先有本地许可） | 本地已有 `license.lic`（首次联网激活后落盘）；或含脱机包的激活码（`&` 后 envelope） |
| **适用场景** | 联网办公环境 | 物理隔离工厂内网，首次激活联网后长期离线运行 |

### 3.5 心跳机制

- **心跳间隔**：默认 300 秒，演示环境强制覆盖为 10 秒
- **后台线程运行**：由 `HeartbeatManager` 在独立守护线程中执行
- **退避重试**：网络异常时采用指数退避（最小 30 秒，最大 30 分钟）
- **暂停/恢复**：支持 `pause_heartbeat()` / `resume_heartbeat()` 控制

### 3.6 回调钩子系统

SDK 通过回调函数将异步事件回传给业务层：

| 回调 | 触发时机 | 业务响应 |
|------|----------|----------|
| `on_license_updated` | 服务端下发了新证书 | 更新 UI 状态、记录日志 |
| `on_activation_required` | 授权被驳回/封禁 | 弹出警告、显示锁定原因 |
| `on_heartbeat_error` | 心跳无法连接/异常 | 若错误码为 300006，自动清理本地缓存 |
| `on_heartbeat_ping` | 心跳成功上报 | 记录日志 |

### 3.7 业务阻断机制

点击业务按钮时：

1. 完整的激活流程被执行（不是仅校验）
2. 调用 `client.validate()` 实时验证授权
3. 若无有效证书或已过期 → 抛出异常，弹出错误提示
4. 若验证通过 → 显示业务层提示："AI 模板匹配算法已成功启动，正在处理图像帧..."

## 4. 安全设计

### 4.1 硬件指纹绑定

- 使用 `mac + hostname + cpu` 等硬件特征计算 SHA-256 哈希
- 许可证与设备指纹一一绑定，非法复制到其他机器将验签失败
- 支持跨平台（Windows/macOS/Linux）

### 4.2 RSA 签名验签

- **算法**：`RSA-PSS-SHA256`
- **证书结构**：`LicenseEnvelope { algorithm, data, signature }`
- **data 字段**：包含完整的授权信息 JSON（license_key, dates, hardware_fingerprint 等）
- **验签流程**：解码 signature → 使用公钥验证 data 的签名 → 解析 payload → 校验指纹与有效期

### 4.3 本地存储加密（可选）

- 通过 `storage_secret` 配置启用 AES-GCM 加密
- 加密格式：`enc:` + base64(nonce + ciphertext)
- 即使 license.lic 文件泄露，无密钥也无法解读内容

### 4.4 授权撤销检测

- 心跳返回错误码 `300006`（许可证不存在）时，自动清理本地缓存
- 防止管理后台删除授权后客户端仍然继续使用

### 4.5 网络 mock 隔离

- 通过 monkey-patch `requests.Session.post` 统一拦截激活与心跳使用的 HTTP 客户端
- 勾选「模拟断网」时应用拦截；**业务校验通过后若仍为断网，不自动恢复**，避免心跳“假成功”
- 关闭「模拟断网」、点击「清理本地许可缓存」、或在不勾选断网时再次运行业务/激活，会恢复真实 `Session.post`

## 7. 许可证文件格式

`license.lic` 文件为 JSON 格式的 Base64 编码内容，解码后结构如下：

```json
{
  "algorithm": "RSA-PSS-SHA256",
  "data": "{\"activated_at\":..., \"authorization_code\":..., "
          "\"end_date\":..., \"hardware_fingerprint\":..., "
          "\"license_key\":..., \"start_date\":..., \"status\":...}",
  "signature": "<base64-encoded-RSA-PSS-SHA256-signature>"
}
```

关键字段说明：
- `license_key`：设备级许可证唯一标识（如 `LIC-DEVICE-E3CB989494260205500B37A3`）
- `authorization_code`：产品级激活码（如 `LIC-207E-tEOWEY54X3tL-zSAA`）
- `hardware_fingerprint`：激活时的设备指纹
- `start_date` / `end_date`：授权有效期范围
- `max_activations`：最大激活设备数

## 8. 错误处理策略

| 场景 | 处理策略 |
|------|----------|
| 无激活码 + 无本地 `license.lic` | 提示需先激活或放置许可文件 |
| 断网 + 本地已有 `license.lic` | 优先用本地缓存验证（直接放行）；验证失败则**保留文件并阻断**，提示联网后重试 |
| 网络不通（在线激活） | 优先用本地缓存（若存在）；若缓存无效且有脱机包 → 降级离线；否则阻断 |
| 硬件指纹不匹配 | 抛出 `hardware fingerprint mismatch`，拒绝运行 |
| 证书过期 | 抛出 `license expired`，拒绝运行 |
| 服务端撤销授权（300006） | 自动清理本地缓存 |
| 签名验签失败 | 抛出 `signature mismatch`，拒绝运行 |
| 内网模式（无脱机包且无本地缓存） | 在线失败且无脱机包 → 阻断 |
